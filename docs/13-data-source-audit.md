# Recurring qualifying data source audit

Reviewed 6 November 2026. This is a finite survey of practical public feeds, maintained archives, official timing publications and commercial APIs. It cannot establish that every dataset on the internet or every private vendor contract has been examined. A documented field, a successful sample request and a validated whole-session import are separate evidence levels.

## Finding and feature decision

**Actual speed, throttle, gear and binary brake data exist.** These four panels can remain in the product plan. They must be populated from their own native source channels. Braking inferred from falling speed is not acceptable. A fresh OpenF1 check on 6 November returned 306 records for 2024 Monza qualifying, driver 4, lap 11, with brake values `{0,100}`, gears 2–8, 31 distinct throttle values and 165 speed values. The [lap record](https://api.openf1.org/v1/laps?session_key=9586&driver_number=4&lap_number=11) supplies the request window; see the repeatable probe in [the source register](09-sources.md).

The survey does not justify removing these features, including from the clearly labelled synthetic preview. No real-data importer is completed by this audit. Preserve the preview while production records acquire explicit channel availability and provenance. An absent native channel becomes unavailable; never generate a replacement from another channel.

Recommended order: FastF1 for whole-session ingestion; OpenF1 as a separately validated alternative; TracingInsights as a maintained archive/backfill candidate; Jolpica for calendar/results; FIA documents for external timing checks. Several options share upstream measurements, so multiple downloads do not necessarily provide independent validation.

## Channel contract for an eventual real import

These are source acceptance rules, not claims that any importer is already implemented. The four existing telemetry panels remain planned. Additional fields below are inventory findings, not an instruction to expand the MVP.

| Display or analysis factor | Acceptable evidence and treatment |
| --- | --- |
| Speed | Native reported km/h; retain timestamps, gaps and source interpolation flags. A dense drawn line does not increase measurement density. |
| Throttle | Native percent channel only. Preserve null/sentinel handling and range anomalies; never estimate from acceleration. |
| Gear | Native integer state, with unknown/missing represented explicitly. Use step rendering; never reconstruct from speed. |
| Brake | Native Boolean or documented 0/100 switch, normalized to on/off. State timing is approximate at the sampling density. Never label it pressure or infer it from deceleration. |
| RPM / DRS | Available source candidates, outside the current four-panel MVP. Validate actual event/year coverage and raw state mapping before adding. A source schema alone does not guarantee a populated 2026 DRS channel. |
| Lap / sector clocks | Recorded durations, matched to the actual lap and phase. Q1/Q2/Q3 classification bests do not enumerate all laps. Preserve source residuals and later corrections. |
| Minisectors / continuous delta | Numeric provider splits only where supplied as durations; otherwise clearly labelled estimates from supported elapsed-time/distance alignment. Color/status arrays cannot produce duration deltas. Sector-only data supports boundary points, not a continuous curve. |
| Track map / turn labels | Reference-lap position plus reviewed layout/approximate markers. No claimed precise racing-line or lateral car-placement comparison. |
| Low/medium/high speed, local gains and class findings | Derived by the documented LapDNA reference, windows and thresholds. State coverage and uncertainty. They are computed comparison results, not upstream sensor channels. |
| Weather / compound / tyre age | Actual source context where present; useful for comparison warnings. They cannot establish a causal explanation or actual tyre surface/carcass temperature. |
| Steering angle / brake pressure / fuel / setup / tyre temperature / energy deployment / measured G-load | Not verified in the selected public native telemetry feeds. Require a new provider's exact measured field, units, timestamps, event coverage and permitted use before any production display. Do not infer these from speed, broadcast graphics or derived acceleration. Private vendor possibilities remain unverified. |

Channel capabilities should be per dataset/lap with coverage diagnostics, not a permanent global assumption. Keep the provider's raw field name, units, native sample count, processing/resampling description, retrieval UTC, source/library version and content digest. Distinguish recorded, interpolated, derived and synthetic values. Do not fill a missing channel from a different provider without a reviewed identity/clock-matching procedure and explicit provenance.

**Pinned-parser checks for T01:** FastF1 3.9.2 can extend incomplete driver records and fill missing numeric values with zero and brake with `False`. Those inserted values must stay masked as unavailable, not become measured coasting or brake-off intervals. The same parser defaults missing raw DRS channel 45 to zero and explicitly notes its absence in 2026. A resulting `DRS=0` alone does not prove a recorded closed state. Inspect raw-channel presence and source-row provenance before normalization; add offline fixtures for both cases. The parser describes usual native car cadence around 240 ms, rather than a guaranteed uniform grid. [Pinned parser implementation](https://github.com/theOehrly/Fast-F1/blob/v3.9.2/fastf1/_api.py)

## Repeatable post-qualifying workflow

1. Discover the selected season's calendar and event identity. Resolve the actual qualifying session rather than assuming a fixed round count, race date or weekend format. A future scheduled event and an imported qualifying dataset are different states.
2. Operator starts an import after session completion. Mark it waiting when data has not been published. Use bounded retries with increasing delay and the provider's Retry-After; stop and report authentication/permission failures. Do not repeatedly retry a permanent missing-data response.
3. Fetch one complete session into a private cache, including all drivers/laps and supporting status/race-control context. Freeze a source-specific snapshot with hashes, source version and retrieval time. An archive fallback gets its own identity and processing record.
4. Verify per-lap phase, completeness, deletion/accuracy status, timestamp coverage and each channel independently. Identify cancelled/absent phases explicitly. Unknown phase membership prevents a misleading Q1/Q2/Q3 selector.
5. Reconcile recorded sectors and laps internally and against the selected FIA report where available. Keep raw residuals. Do not make the curve fit the answer and then claim independent agreement.
6. Generate eligible comparisons, local estimates and supported observations only for their permitted result tier. Publish immutable datasets/cards after quality checks. Recheck late deletions/corrections; a changed source creates a revision and invalidates dependent caches, retaining the previous provenance.
7. Display ready / partial / waiting / unavailable with the reason. Source outage, no selectable lap and no recorded brake channel are different conditions. Keep raw data and secrets outside Git and check distribution terms before publishing data artifacts.

This document specifies an import procedure; it does not create an unattended schedule or promise instant availability. None of the public community sources establishes an SLA for every qualifying session. Local cached results should stay usable during upstream outages.

## Verification record and remaining gates

- Search date: 6 November 2026. Search groups covered native F1 telemetry feeds/libraries, post-session archives, calendar/results, official timing reports, circuit geometry, academic/static datasets, commercial sports APIs and game-telemetry false matches. Queries included `Formula 1 telemetry API brake throttle qualifying`, `F1 dataset download telemetry post session`, `Formula 1 qualifying minisector timing API`, and provider-specific schema/coverage searches. The linked primary pages were reviewed; third-party search snippets were not treated as channel contracts.
- Native sample check: the dated OpenF1 check above extends the 5 November probe in the source register. It retrieves one lap window and prints aggregates without saving raw files. It establishes actual channel availability for that sample, not end-to-end comparison quality or continuous service availability.
- No commercial subscriptions, trial accounts, credentials, full-season downloads or new FastF1 authentication session were created for this survey. Several vendor schemas and redistribution terms remain unverified.
- The source registry in [config/data-sources.json](../config/data-sources.json) is a research inventory. A `documented` capability is not a completed adapter. T01 still requires a whole-session import, sanitized manifest and actual access/failure checks; T02–T05 own eligibility, alignment and evidence validation.
- Before adding any sensor feature, obtain its exact field definition and a real sample, verify its measurement/derivation status and qualifying coverage, then apply the same source-fidelity rules. Before dropping a proposed feature, record which surveyed sources were checked and the specific missing evidence. This survey preserves the existing demo pending that review.
